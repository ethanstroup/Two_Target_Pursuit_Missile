41. The phi_2 = 0 corner segment O - f_1 - e_1 (the paper's other family)
==============================================================================
  Table 2 O_1  = (R 6.1416, phi_1   0.00 deg, phi_2  0.00 deg)
  Table 2 f_1  = (R 6.1420, phi_1  18.50 deg, phi_2  0.00 deg)
  Table 2 e_1  = (R 6.1420, phi_1  36.07 deg, phi_2  0.00 deg)
  -> all three sit at phi_2 = 0 and R = Rbar(0) = 6.14159, differing only
     in phi_1.  They are collinear along the corner edge, not on the lens.

  Rbar has a corner at phi_2 = 0: Rbar = Rbar_0 - |phi_2 + sin phi_2|,
  so dRbar/dphi_2 jumps from +2.0000 to -2.0000 across it.
  The outer normal is therefore not unique there, and the costate must
  be a non-negative combination of the two adjoining normals:
     n(phi_2 -> 0-) = (1.000, 0.000, -2.000)
     n(phi_2 -> 0+) = (1.000, 0.000, +2.000)

  barrier.py CAN solve that combination: lam_corner solves H* = 0 and
  FI = 1 for it.  Scanning phi_1 along the corner:
     phi_1 intervals admitting TWO admissible costates [deg]: [(np.float64(36.1), 44.8)]
     the corner costate becomes double-valued at phi_1 = 36.0755 deg
     Table 2 e_1 is at                              phi_1 = 36.07 deg (difference 0.0055 deg)
     -> e_1 is precisely the branch point of the corner costate. Below it,
        along O - f_1 - e_1, the corner costate is UNIQUE:
        at f_1   lam_corner        = (+0.9574, +0.0000, +1.7737)  sigma_2* = +1
        cf.      lens, phi_2 -> 0- = (+0.9509, +0.0000, -1.9017)  sigma_2* = -1
        cf.      lens, phi_2 -> 0+ = (+0.9509, +0.0000, +1.9017)  sigma_2* = +1
  >> Wiring lam_corner into the seeding is necessary but NOT sufficient: on the segment O - f_1 - e_1 it returns a single costate, matching the phi_2 -> 0+ limit. Two sheets over that segment -- which is what a dispersal line needs -- do not fall out of it as written.

  Does the seeding ever use it?
     bup_curves.py references lam_corner   : NO
     bup_curves.py references n_maxrange   : NO
     bup_curves.py references n_minrange   : NO
     bup_curves.py references n_boresight  : NO
  >> The phi_2 = 0 corner family is NEVER SEEDED. bup_curves.py builds seeds only from lam_maxrange / lam_minrange / lam_boresight -- the three smooth surfaces. lam_corner is implemented and validated by test_barrier.py to 1.1e-15, but nothing calls it. So of the paper's two maximum-range families, only the lens family (e_1 d_1 O) is generated; the corner family (e_1 f_1 O) is absent.
  >> Because the corner family is absent, the dispersal line where the two families meet cannot be produced, c_1 cannot be located, and the two small closed capture zones cannot be bounded. What is plotted today is the ordinary backward-integrated sheets only.

7. Universal / singular control at the special points
==============================================================================
  At d_1 (and at f_1 on the corner) lambda_1 = 0 AND lambda_1-dot = 0,
  so sigma_1 = -sign(lambda_1) determines nothing.
  barrier.py behaviour: integrate_retrograde DETECTS this case
  (|lambda_i| < tol and |lambda_i-dot| < tol) and returns it in its
  `singular` field.  Flags raised over this bundle: 0
  smallest max(|lambda_i|, |lambda_i-dot|) anywhere in the bundle: 1.93e-03
  detector threshold: 1.0e-07
  >> The singular detector never fires: the closest any trajectory comes to the condition is 1.9e-03, five orders of magnitude above the 1e-7 threshold. It is dead code in practice and provides no protection.
  >> There is NO singular / universal-arc propagation anywhere in the code. Universal lines are detected, never integrated. The intermediate control on such an arc is not computed, and nothing assigns sigma_1 = +/-1 there as a substitute.
